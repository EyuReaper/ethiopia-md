# Ethiopia.md documentation

This folder holds the working documents behind the knowledge base. The rules for writing articles live in [`EDITORIAL.md`](../EDITORIAL.md), and the contribution workflow lives in [`CONTRIBUTING.md`](../CONTRIBUTING.md). The files here are supporting material for those two documents.

## Index

| Path                                                               | What it covers                                                                       |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------ |
| [`editorial/QUALITY-CHECKLIST.md`](editorial/QUALITY-CHECKLIST.md) | A pre-submission checklist for an article, in the order a reviewer reads it.         |
| [`editorial/TRANSLATION-SYNC.md`](editorial/TRANSLATION-SYNC.md)   | How to keep the English translation in step with the Amharic source.                 |
| [`prompts/TRANSLATE_PROMPT.md`](prompts/TRANSLATE_PROMPT.md)       | A prompt to hand to an AI assistant for translating an Amharic article into English. |
| [`prompts/CONTRIBUTE_PROMPT.md`](prompts/CONTRIBUTE_PROMPT.md)     | A prompt to help someone draft a new article that follows the editorial rules.       |
| [`community/TRANSLATION-BOARD.md`](community/TRANSLATION-BOARD.md) | Where to see which articles still need an English version.                           |
| [`community/GOVERNANCE.md`](community/GOVERNANCE.md)               | Who makes decisions about the project today.                                         |

## Related files outside this folder

- [`EDITORIAL.md`](../EDITORIAL.md): article structure, frontmatter, sourcing, and the rules for Ethiopia-specific facts.
- [`CONTRIBUTING.md`](../CONTRIBUTING.md): how to submit a change.
- [`i18n/README.md`](../i18n/README.md): how the Amharic and English language tiers fit together.
- [`scripts/README.md`](../scripts/README.md): what each build, validation and tooling script does.
- [`ROADMAP.md`](../ROADMAP.md): what is planned and what is still open.

## Keeping these docs honest

A document in this folder should describe something the repository actually does. If a process is described here, a script, a workflow or a person should be responsible for it. If a document describes a feature that has been removed, delete it rather than updating the wording.
